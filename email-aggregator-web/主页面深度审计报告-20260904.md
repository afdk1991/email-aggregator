## 1. CSS 样式一致性、颜色方案与主题规范

### 1.1 设计令牌系统化（P0 完成）
原 `:root` 仅 11 个令牌，全文散落 12+ 处 `var(--x, #fallback)` 兜底值与硬编码色。本轮补全 **28 个令牌**：

```
颜色：--bg --panel --panel-2 --border --text --muted
      --primary --ok --ok-text --ok-bg
      --err --err-text --err-bg
      --accent --accent-text
      --pending --pending-text --pending-bg
阴影：--shadow-sm / --shadow-md / --shadow-lg
圆角：--radius-sm(6) / --radius-md(8) / --radius-lg(12)
```

- **消除硬编码**：全文 `0 2px 8px rgba(...)`、`border-radius: 999px` 等散落值统一替换为 `--shadow-*` / `--radius-*`。
- **对比度合规**（详见 §5）：`--err-text:#b91c1c`、`--ok-text:#15803d`、`--pending-text:#b45309`、`--accent-text:#d13a43` 全部 ≥ 4.5:1（见 §5 色板验证）。
- **收益**：主题切换、暗色模式预留只需改 `:root`，符合「主题规范」要求。

### 1.2 颜色方案审查
- 主操作蓝 `--primary:#2563eb`、危险红 `--err`、品牌红 `--accent` 三色分工清晰，无语义冲突。
- 状态色（ok/err/pending）均由「背景 + 文字」成对令牌组成，文字色专门加深以满足对比度。
- ⚠️ **遗留建议（P2）**：`--accent` 与 `--err` 视觉接近（红系），列表未读标记用的是 `--accent`、删除危险按钮用的是 `--err`，两者在快速扫视下易混淆，建议未读标记改用中性或主色系以拉开语义距离。

## §11 三项增强落地（2026-09-05，P1-2 / P2-3 / P2-4）

### P1-2 邮件列表虚拟滚动 ✅

**问题**：千级邮件（real 139 e2e 已验证 2389 封）全量渲染 DOM，节点数过多影响性能。

**方案**：固定行高窗口化（过度工程化避免——小列表不虚拟化）。
- 阈值 `VIRTUAL_THRESHOLD = 50`：超过才启用虚拟滚动，≤50 项全量渲染。
- 固定行高 `ROW_HEIGHT = 80px`（与 CSS `.mail-item { height: 80px; overflow: hidden }` 同步）；preview 已有 `ellipsis` 截断保证单行。
- `ResizeObserver` 测量容器视口高度；`onScroll` 更新 `scrollTop`；计算 `[startIndex, endIndex]`（上下各 `BUFFER = 5` 行缓冲减少白屏）。
- 用 `paddingTop/paddingBottom` 撑开总高度（保留文档流，避免 absolute 定位复杂性）。
- 每个可见项加 `aria-posinset` / `aria-setsize`，屏幕阅读器感知列表完整性。
- **保留**：onClick / onKeyDown(Enter+Space) / 未读点 / 未读类名 / 排序逻辑（未读上移）。
- **不虚拟化**：检索命中分支（hits 通常较少，保持全量渲染）。
- CSS：`.mail-list.virtual { max-height: calc(100vh - 220px); overflow-y: auto; overscroll-behavior: contain }`。
